# Maintenance notes

## Boundaries

- `crates/bkpr` owns the native launcher, Git/CI, SSH forwarding and typed state contract. `crates/bkpr-zellij` owns WASI sidebar, finder and passive overlays. Zellij owns PTYs, input, native panes/tabs and session persistence; never mirror terminal output through the plugin.
- Keep workspace-first grouping and stock Zellij controls. Application input starts Locked; Ctrl+Space focuses sidebar controls. Passive details and shortcut cards never take keyboard focus or move the application cursor. Finder alone is a focused modal. Native splits/tabs must remain discoverable; close terminates, not hides.
- Recognized harness status comes only from OSC 7501. Process/CWD recognition and OSC 0/2 titles are separate. Generic programs do not get harness-status badges; Git/CI remains available to them. Do not infer semantic state from titles, progress, output or process presence.
- Do not change a user's harness profiles, persistent third-party settings, credentials or GitHub account. Claude's launch-local hooks supplement titles and capture native session IDs; launch-local MCP communication does not produce harness status. Antigravity is recognition-only.
- Prefer Bkpr-owned APIs and push events. Add changes to the native fork only when its plugin/launcher API cannot provide the behavior; keep each change on a retained feature branch.
- Preserve attachment to existing sessions across changes whenever reasonably avoidable. New features may require a fresh native session; ordinary attachment must not. Keep legacy session configuration, plugins and launch wrappers intact. Mark every temporary compatibility path and its dedicated tests with `LEGACY_COMPAT(next-major)`, explain its purpose, and remove it at the next major release.
- Clipboard transport belongs to the native fork, not WASI. Bkpr enables queries only in its private native configuration; host terminal permissions remain authoritative. Preserve exact MIME data and wire framing, never turn clipboard replies into keyboard input, and bind paste grants to their original pane, client and clipboard selection. Timeouts and malformed transfers must not fabricate clipboard contents.

## Git, provider and agent data

- Associate repositories with foreground CWD and the canonical common Git directory; linked worktrees have independent HEADs. Committed whole-repository totals compare HEAD to a merge-base. A PR target commit overrides guessed local bases; a missing target does not fall back to main. Never fetch for UI.
- Git watches invalidate cached state and trigger new-commit/push refresh. Cold forge data loads eagerly and is shared/batched. Only published, non-green checks use the 60-second refresh loop; complete green/skipped/no-check and unpublished results idle. Respect shared spacing, provider limits and backoff.
- Persist per-canonical-CWD metadata in XDG state. Validate repository, branch, HEAD and refs on restore. Linear associations come from canonical links in rendered PR comments, not personal mappings or speculative parsing. Popups/finder share typed metadata and link only verified destinations.
- Communication identities are authenticated and launch-scoped; never adopt an exited launch's inbox implicitly. Sends require sender-scoped idempotency keys matched against the exact recipient, text and scope; retain receipts after acknowledgement and expiry. Broker protocol changes fail closed against old processes, never restart a live broker automatically.
- Native workspace membership is independent of repositories and receiver readiness. Discovery excludes self and defaults to the current foreground Bkpr workspace; session/repository/all are explicit scopes. Unknown context fails closed, and detached native app-servers never become workspace peers through their lease alone.
- Inject `BKPR_SESSION_ID`, `BKPR_SESSION_NAME`, `BKPR_WORKSPACE_ID`, `BKPR_WORKSPACE_NAME` and `BKPR_PANE_ID` before every native pane exec, not only harness launch. These are immutable process snapshots; `bkpr context --json` reads live labels/membership. Canonical bindings are native-owned before spawn; reused native tab IDs must not reuse closed workspace identities. Unmanaged nested runtimes clear inherited context.
- Publish context with the private startup native-owner configuration, monotonically reserved helper sequences and server birth identity. Readers and delayed publishers require the exact native owner's externally held advisory lease; unload/crash invalidates it synchronously. Never expose the owner token or opt-in marker through pane environments, sidebar configuration or public session environment queries.
- Bridge registration is not readiness. Track native binding, live helper/extension identity and actual subscriber connections separately, without inventing semantic harness status. Coalesce opaque inbox notifications into future turns; never steer an active turn. Distinguish durable acceptance, wake acceptance, reading and processed acknowledgement. Never blindly replay ambiguous wakes; guard callbacks by notification generation and retain their outcomes after reads.
- Preserve unacknowledged bodies for seven days after the first persisted broker observation of recipient exit; read-only diagnostics must not start that clock. Purge bodies at known deadlines while retaining receipt/failure metadata. Suspend every commit path after durable-store failure, including asynchronous callbacks, until restart and reconciliation.
- SSH forwarding is launcher-owned: the latest live managed attachment selects the upstream agent, unset/no client fails closed. Keep the stable pane socket across helper restarts, preserve raw Unix path bytes, serialize startup/cleanup and guard in-flight requests by generation.

## WASI and UI invariants

- Render complete frames: Zellij clears the plugin grid each render. WASM stdout also transports host commands; emit commands before frame text and flush every render. Acknowledge every CLI-pipe input, including bootstrap/EOF. Cache cursor commands and avoid redundant redraws.
- All plugin roles request the shared `PERMISSIONS` set; permission grants are cached per WASM path and role requests replace them. Sidebar startup applies creation-scoped snapshot/guide/view only after grant; live `STATE` remains authoritative. Keymap publications must be immutable, session/client-scoped and byte-validated.
- `mode_info_format="json"` plus `ModeUpdate`/`InitialKeybinds` preserves native key identities. Cache the keymap separately from scalar mode updates. Strip native-only layout flags before strict application-config validation.
- Use terminal-default foreground/background and semantic ANSI colors, never a fixed RGB theme. Derive muted/shaded styles only from query-confirmed truecolor and actual client-specific terminal colors; Zellij UI-theme RGB is not capability evidence. Cache SGR styles on effective palette changes, and preserve each event's client destination through pending load/permission replay. New sidebar/finder/popup roles need the current host palette snapshot; missing metadata stays ANSI-native.
- Sidebar rendered columns exclude its resize gutter; outer pane geometry does not. Layout metadata `shared_tiled_width_group` / `shared_tiled_width_initial` opts into native session-wide outer-column intent. Keep it across tabs and temporary client-size clamping; preserve outer width when creating tabs. The details card may cover exactly one separator cell, never painted item cells; the separator remains mouse-resizable.
- `-d` / `--detach-others` is an opt-in, single-attachment operation. Keep the exact newly attached client and release other clients' screen/plugin state without waiting for their exit acknowledgement; never close their panes/programs or repeat takeover during sidebar reloads. Negotiate support on that attachment's own IPC connection, tolerating flow-control acknowledgements before the capability reply; legacy servers fail before anyone is detached.
- Popup helpers are client/launch scoped. Ignore foreign/stale frames. Present a cleared or exact-size frame before acknowledging READY, accepting pointer actions or showing content; native show resets suppressed coordinates, so place after show. Genuine helper faults belong in the sidebar, not a transient red card.
- Sidebar hover and popup hover cannot both own the physical pointer. Keyboard navigation invalidates an earlier mouse highlight; do not let stale native pointer coordinates pin a focus-only popup. Probe the helper at handoffs without polling, and let verified popup hover retain details after sidebar leave.
- Locked shortcut hints stay inline. Wider cards are used only when keys/descriptions would wrap at sidebar width; a widened sidebar card uses normal adjacent anchoring, never the far-right edge. Plan content height and geometry before display, not when READY arrives. Finder coordinates cover the whole display.

## Releases and commits

- Use Conventional Commits for new commits: `feat:` for user-visible features, `fix:` for fixes, and `type(scope):` when a scope helps. Mark breaking changes with `!` and a `BREAKING CHANGE:` footer. Maintenance-only commits use `chore:`, `docs:`, `test:`, or `refactor:`; do not label them as features or fixes to force a release. The manual release workflow derives SemVer and release notes from these messages; earlier nonconforming history is not rewritten.
- `unstable` is a moving cache tag. Version tags are immutable `vMAJOR.MINOR.PATCH` SemVer releases (optional prerelease/build suffixes); publish release assets only after the tagged cache build succeeds.

## Development

Use `nix develop` and incremental debug Cargo artifacts in `target/`. Use `just build` to build the launcher and WASI plugin together, and `just run [args…]` to build both before launching with the matching plugin. Run coordinated checks once after edits: `cargo test --locked --workspace`, `cargo build --locked -p bkpr-zellij --target wasm32-wasip1`, host/WASI `cargo clippy --locked ... -- -D warnings`. Use `nix build .#bkpr` only for packaging validation, not the edit/run loop.

### Forked Zellij runtime

The pinned host is [calops/bkpr-zellij](https://github.com/calops/bkpr-zellij), based on Zellij 0.45.1. Stock Zellij lacks required OSC/plugin event contracts. The fork's default `main` contains the Bkpr integration history; there is no separate `bkpr` integration branch or permanent upstream branch. Retained `feature/*` branches submit PRs into `main`. Bkpr consumes `github:calops/bkpr-zellij/main` and pins its revision in `flake.lock`; do not restore a local patch queue or override the fork's locked dependencies with `follows`. Bkpr's release CI owns the shared binary cache. Ordinary native feature PRs rely on local/integration verification and human review, not a global Rust CI status.

The fork polls stable Zellij releases daily and opens `update/zellij-vX.Y.Z` PRs from release tags, never upstream's moving `main`. Updates preserve upstream ancestry with merge commits. Every PR requires human validation and explicit manual merging, even when conflict-free and CI-green. Protected `main` requires PRs, with no mandatory approval count or global CI status. Only release-update PRs run the fork's Nix/package verification and publish `Upstream verification`. Auto-merge, squash merging and rebase merging are disabled; preserve merge commits.

Normal Bkpr development is `nix develop`, then `just run --session dev`. The shell supplies `just` and the pinned native runtime; the recipe builds both debug components and selects the matching WASM, including with `CARGO_TARGET_DIR`. Plain `cargo run --locked -p bkpr` builds only the launcher, so the WASI plugin must be built separately. Use `--zellij ../bkpr-zellij/target/debug/zellij` to select an incremental native build explicitly; the argument is an executable path, not a checkout directory. Use incremental Cargo artifacts for tests and iteration, not `nix build`; reserve Nix builds for explicit packaging validation.

For native changes, clone the fork beside Bkpr and work on a retained feature branch. In that checkout:

```sh
nix develop --accept-flake-config
cargo build --locked --offline --no-default-features
```

Run Bkpr from its own devshell with `just run --zellij ../bkpr-zellij/target/debug/zellij --session native-dev`. Start a fresh session to use new host features; existing servers retain old code and must remain attachable where reasonably avoidable. After local/integration verification, push the retained feature branch and open a PR into the fork's `main`. Human-validate it and merge explicitly with a merge commit; never enable auto-merge, squash or rebase merging. Do not dispatch release-update CI for an ordinary feature PR. After the PR lands, update Bkpr's input with `nix flake update bkpr-zellij`, preserving the fork's dependency pins. The fork's [Nix notes](https://github.com/calops/bkpr-zellij/blob/main/docs/NIX.md) document package outputs and offline vendoring.

Test focus, cursor, physical mouse, resize and hyperlinks in an actual isolated terminal, not just unit tests or injected escapes. Smoke scripts go under `target/smoke/`, using devshell Python+pyte and `sys.executable`; isolate HOME/XDG, inherited multiplexer and credential variables, and private native sessions. Never touch live sessions or call real model/provider services for a fixture. Clean up owned processes/files, retain useful evidence, and keep README user-facing.
