- [ ] Keep the private Bkpr Zellij socket directory out of ordinary pane environments if we decide that stock `zellij` launched inside a Bkpr pane must not see Bkpr sessions. Today the launcher sets standard `ZELLIJ_SOCKET_DIR` only for its patched Zellij client/server, and the detached project watcher sets it explicitly; the server passes it on to pane programs. A small patch at Zellij's pane-process spawn could replace it with a `BKPR_*` variable. Bkpr helpers would then translate that value back to `ZELLIJ_SOCKET_DIR` only when invoking our patched host. Test arbitrary splits, reattach, detached watcher updates and in-pane Zellij CLI commands before changing this: removing the standard variable also changes how those commands find their session.

The near-term choice is to keep Zellij's standard environment contract and isolate its sockets via the wrapper, without a pane-environment change. The fork reports `zellij 0.45.1-bkpr.2` so the launcher does not accept stock or stale Bkpr runtimes. Native changes live on retained feature branches in `calops/bkpr-zellij`, submitted as PRs into its integrated `main`; remove them when upstream covers their contracts. Stable upstream releases arrive as human-validated, manually merged update PRs that preserve ancestry. Bkpr pins the fork's `main` flake without overriding its dependency locks, and its release workflow builds and caches that dependency through Nix. Releases publish notes without binary assets until distro-specific packages are available. An external stock Zellij becomes viable only after it provides the required Bkpr contracts.
