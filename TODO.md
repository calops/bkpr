- [ ] Keep the private Bkpr Zellij socket directory out of ordinary pane environments if we decide that stock `zellij` launched inside a Bkpr pane must not see Bkpr sessions. Today the launcher sets standard `ZELLIJ_SOCKET_DIR` only for its patched Zellij client/server, and the detached project watcher sets it explicitly; the server passes it on to pane programs. A small patch at Zellij's pane-process spawn could replace it with a `BKPR_*` variable. Bkpr helpers would then translate that value back to `ZELLIJ_SOCKET_DIR` only when invoking our patched host. Test arbitrary splits, reattach, detached watcher updates and in-pane Zellij CLI commands before changing this: removing the standard variable also changes how those commands find their session.

The near-term choice is to keep Zellij's standard environment contract and isolate its sockets via the wrapper, without a pane-environment patch. The patched host reports `zellij 0.45.1-bkpr.1` so the launcher does not accept stock 0.45.1. We retain an ordered upstream patch queue and remove patches as upstream releases cover them. Nix users can use the flake; the release workflow builds a separate three-file native archive instead of exporting a Nix store closure. An external stock Zellij becomes viable only after it provides the required Bkpr contracts.
