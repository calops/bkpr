# bkpr-tui-framework

## Boundary

Reusable terminal composition, host input/reply framing and physical output infrastructure. Depend on protocol, not core/client; terminal-engine is test-only. Application navigation/content/policy belongs to client. Consume canonical pane scenes, never reparse pane VT into another emulator. Keep one coordinated output owner for cells, graphics, cursor and terminal modes.

## Entry points and contracts

- `render.rs` owns host modes, input/reply demultiplexing, device probes and clipboard framing. `scene.rs` is included in that renderer scope and supplies composition, clipping, damage, resources and hit maps. Separate device replies from keys before maintained input decoding; bracketed paste stays literal even when it contains escape/reply-looking bytes.
- Scene surfaces are borrowed and ordered. Hit maps describe the exact submitted cell geometry; graphics-only layers do not acquire input ownership. Preserve complete wide/combining glyphs, source-local clips and canonical frame/image immutability. Selection/search/palette/faint annotations are client-local projection, not baseline mutation.
- Image identities combine ownership/generation and stable surface identities; native image IDs alone are not globally unique. Derived projection resources have bounded inactive residency and lazy upload. Plan composition/occlusion before writes; a failed output is not proof that the host remained unchanged.
- `image_resources.rs::ImageManifest` caches validated descriptor lookup. `Surface.image_manifest = Some(...)` explicitly permits declared pending resources; `None` keeps strict fully-resident validation. Visibility, pending picking and ready projection share geometry; a pending top image must not fall through to a lower ready image. Local resource arrival can repaint unchanged backend scene revisions.
- `SurfaceContent::Annotation(Rect)` paints tight source-local cells without images, hit ownership, focus ownership or logical-cursor occlusion. Default colors inherit the already-composed underlay, including inverse/native-default semantics; explicit colors remain caller-owned. With confirmed RGB and known backdrop color, default ink over blank cells chooses the higher WCAG contrast of the caller's normal frame colors using Palette; unknown defaults stay native. Use it for passive loading/error feedback, not duplicate native surface IDs or another output path. `loading.rs` supplies delayed visibility/deadline mechanics; callers own labels, colors, initial delay and pending/failure policy.
- `graphics.rs`, `decoration.rs` and `joined.rs` prepare ordinary scene resources off-thread. Worker caches, wake descriptors and readiness do not create another terminal writer. Missing decorative readiness retains text fallback; do not weaken meaningful content or lower fidelity for speed.
- Stretched atlas strips sample an interior texel with identical neighbors. Sampling a tile boundary lets host filtering bleed adjacent opaque corner pixels into transparent gutters; even minimal atlases need three texels per tile axis.
- `graphics_cache.rs` uses typed Rustix filesystem/lock APIs and Tempfile atomic creation for one caller-owned, private shared cache: 128 MiB including pending writes, 256 entries, admission-time LRU trimming to 75%, and at-most-hourly touches. All versions share the same budget. Unknown/unsafe paths or contention bypass disk; only recognized orphan temporary files are reclaimed under the lock. No cache daemon, rendering-path I/O, or pane contents.
- `raster_cache.rs` keys reusable SVG masks, complete decoration atlases and visible joined contour body/shadow patches by full visual inputs, dimensions, channel format and raster implementation fingerprint. Entirely invisible patch pairs and complete joined layouts remain memory-only: empty tile variants otherwise churn the entry limit and evict useful atlases. Input key formatting is internal and streaming; changing raster sources invalidates old entries without creating an unbounded version directory.
- `prepared_png.rs` verifies/encodes on workers and pairs PNG transport bytes with weak immutable image allocation identity. The terminal's bounded encoded registry survives scene key aliasing but never matches native IDs alone. Warm loads retain original PNGs for `f=100`; decoded pixels remain available for canonical composition. Verify zlib completion with the maintained streaming decoder as well as bounded Reader validation: Reader alone may drain a later IDAT trailer without inflating it.
- `surface.rs`/`theme.rs` retain trusted UI text/styles and observed default-color roles. `animation.rs` schedules sparse visible effects; idle or hidden content must not gain periodic repaint. `chord.rs` owns shared modifier/group geometry and Unicode cell widths; application descriptions/priorities remain client-owned.
- `color.rs` resolves cached sRGB base/bright/muted families through Palette. Fixed tones select Okhsl lightness/saturation; vivid tones maximize Oklch chroma at the source hue subject to caller-selected actual-background WCAG contrast. Start at Palette's Okhsv gamut cusp and search both lightness directions with quantized-byte contrast checks; no named-hue corrections or local gamut mapper. Callers cache variants on palette changes, not per cell or animation tick. `TextSweep` consumes elapsed time with terminal-cell velocity and fixed-width bands. Repeated bands use nearest periodic distance and one ink blend per cell, independent of wave count; its clock is dormant without visible work.
- Trusted UI text uses the allocation-free root `text_width` API: sum `unicode-width` widths of whole extended graphemes. `text`, `window::fit`, inputs, keycaps, lists and toasts share that geometry. Sanitize before measurement; native canonical frame widths remain authoritative. UI graphemes wider than canonical cells allow use equal-extent scalar cells when representable, otherwise a visible replacement plus padding preserves their measured extent and source strings.
- `image_viewer.rs` picks canonical image placements and presents full immutable resources through the existing scene compositor. Callers own input/modifier policy and capability gating; source crops affect picking, not the viewed pixels.
- Navigation, list/input, overlay, toast and window modules provide reusable interaction/layout primitives, not Bkpr workspace authority.
- `search_list.rs` owns fuzzy query/ranking and shared painted row geometry. Optional initial selection supports empty lists; replacement retains query and exact surviving identity. Hover selection and pointer acceptance are separate caller policies. Borrow `visible_items` after painting for semantic foreground annotations; application status/authority stays outside the widget.
- `notification.rs` owns correlated OSC 99 discovery, bounded/base64 output and activation/close decoding through `ReplyDemux`. `TerminalGuard` retains the physical probe, initially unknown focus and at most `notification::MAX_ACTIVE` owned presentation IDs. Only exact CSI focus reports receive the protected internal `focus;` tag. Capabilities need a current correlated query; callbacks need live ownership and requested reporting. A query identifies neither a desktop destination nor provider acceptance; terminal writes stay unknown. Closure reports are opt-in, and an untracked report does not release ownership. Caller policy and validated source navigation remain outside the framework.

## Host ownership and evidence

`TerminalGuard` restores owned image/notification resources, keyboard/mouse/theme/paste modes, raw mode and the original background. Notification output and cleanup share the existing terminal writer; no independent provider/output loop exists. Partial notification writes retain cleanup ownership but cannot enable callbacks or establish display. Background query mediation retains original XParseColor spelling/precision and handles replies crossing matte restoration. Unknown capability state is not unsupported. Preserve positive truecolor evidence independently from palette/theme observations; graphics queries bind exact IDs and expire independently. No TERM-name guessing.

Clipboard consent/transfer state is caller-owned. Preserve exact MIME bytes, selection and original offer correlation. Routing identity does not itself validate payloads or grant consent. Malformed/expired transfers must never become keyboard input or fabricated contents.

## Dependencies and verification

Retain maintained infrastructure: termwiz input parsing, Crossterm terminal mechanics, resvg/image/PNG graphics, Unicode width/segmentation and nucleo matching. Default features are disabled for termwiz/Crossterm/image/resvg; inspect actual enabled features and real usage before pruning. Large dependency counts alone do not justify custom parsers/rasterizers or widget frameworks. Re-evaluate an upstream widget foundation when concrete shared behavior benefits, not to add a second render loop.
- OSC 99 reuses existing Base64/UUID/framing infrastructure. Evaluated [uncurses 0.0.7](https://docs.rs/uncurses/0.0.7/uncurses/ansi/notification/index.html) (MIT, released October 2026): its raw metadata encoder does not supply correlation, discovery or activation, and adds a competing rendering library for trivial framing. [beer-protocols 0.14](https://docs.rs/crate/beer-protocols/0.14.0) (EUPL-1.2, November 2026) provides emulator-side codecs, not this client transport. [notify-rust 4.19](https://docs.rs/notify-rust/4.19.0/notify_rust/) (MIT/Apache-2.0, November 2026) is a native client-provider candidate, not framework infrastructure. No new dependency was added for terminal notifications.
- Perceptual color normalization uses [Palette 0.7.7](https://docs.rs/palette/0.7.7/palette/okhsl/struct.Okhsl.html) (MIT/Apache-2.0, August 2026), with only `std`, for gamut-aware hue-preserving Okhsl targets. Evaluated maintained [Linebender color 0.3.3](https://docs.rs/color/0.3.3/color/struct.DynamicColor.html) (MIT/Apache-2.0, May 2026); its Oklch transforms do not provide equivalent gamut-aware saturation normalization. Do not replace this math with a local gamut mapper. Palette's named-color, random, serialization and wide-vector features remain disabled.
- Persistent raster caching reuses [Rustix](https://docs.rs/rustix/1.1.5/rustix/fs/index.html) (`fs`/`process`, Apache-2.0/MIT) and [Tempfile](https://docs.rs/tempfile/3.27.0/tempfile/) (MIT/Apache-2.0), already present transitively, rather than owning POSIX primitives. [Cacache 13.1](https://docs.rs/cacache/13.1.0/cacache/) supplies concurrent content-addressed storage/integrity, but its indexed/content/temp storage API does not supply this cache's single hard entry/byte budget including in-flight files or bounded LRU admission; it would still need policy/accounting around multiple stores. The flat bounded store uses filesystem metadata instead of adding a catalog. PNG 0.18 handles codecs; existing SHA-2 0.11 handles versioned visual-input digests.

Follow root shared Cargo/artifact ownership. Framework code changes need grouped workspace tests, strict all-target Clippy, formatting, warnings-denied rustdoc and actual changed-path smoke. Exercise native terminal surface when changing visible output/input/mode restoration; use isolated HOME/XDG, immutable binaries, one input reader, real device replies and owned cleanup. Existing renderer/geometry regressions cover occlusion, wide cells, resource generations, frame damage, clipboard framing and capability evidence. Retain sanitized evidence under target/smoke; no live user-session fixtures.
