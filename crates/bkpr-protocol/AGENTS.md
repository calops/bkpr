# bkpr-protocol

## Boundary

Shared domain types, pure validation, control schemas and bounded codecs. Every other first-party crate consumes this crate; never depend on their implementations. Authorization, process ownership, persistence, provider I/O and UI policy belong to consumers. Blocking framing helpers do not own connections.

## Working entry points

- `lib.rs` re-exports domain types and defines native family, resource limits and pane/view requests. Public API documentation is enforced with `deny(missing_docs)`.
- `channels.rs` exposes session-local channel operations and typed replies. The caller supplies neither authority nor session identity. Archive discovery identifies closed workspaces with retained channels by ID, without requiring a recoverable workspace name. Saved explicit member IDs are independent of the currently eligible mention roster.
- `registry.rs` carries revision-checked registry operations and typed failure outcomes. `control.rs` generates CLI/MCP argument decoding, discovery and schemas from one allowlisted catalog; core still checks scope/ownership.
- `wire.rs` and `wire/framing.rs` encode/decode native requests, responses and client-lifetime events. `remote_wire.rs` is a separate SSH attachment handshake/lease protocol, not a second native transport.
- `administration.rs` freezes the version-one `BKPA` inspection/identity-checked-stop channel. It uses existing Serde JSON for tiny bounded cold-path policy, not native data-plane compatibility or a generic RPC SDK.
- `scene_wire.rs` encodes canonical frames and complete changed-row replacements. `DecodedScene::apply` checks fallible baseline prerequisites before mutating the consumer's frame/revision.
- `path_wire.rs` preserves non-UTF-8 Unix path bytes at JSON boundaries. `Payload`/`PanePayload` keep binary scenes separate from metadata; JSON conversion is diagnostic, not a native fallback.
- `image_source.rs` names `planus_v1_sources`, selects an image's original PNG/zlib payload when it is no larger than its pixels, and decodes such payloads with bounds: exact-length zlib inflation in 64KiB turns rejecting trailing data, and PNG expansion to the engine's RGBA with dimensions checked before pixel allocation.

## Contracts and pitfalls

- `PROTOCOL_VERSION` is the native family (currently 11); `remote_wire::VERSION` is independent (currently 2). Package versions do not establish compatibility. Evolve compatible tables through optional/default-safe fields and append-only ordinals; retire removed slots permanently rather than reusing them. Removing `SendMessage.delivery` is compatible with an older reader's conservative `Notify = 0` default: preserve its deprecated trailing slot. Reject obsolete diagnostic JSON fields, unsupported mandatory semantics and genuinely mismatched native families. Preserve schema ordinals, enum tags, required-capability rejection, presence checks and aggregate expansion budgets: aliased offsets can expand beyond wire size.
- `PaneRequest::Colors` distinguishes virtual defaults (OSC 10/11), observed indexed base colors (the full `palette` and independent `observed_ansi`) and the pane theme's `ansi` overlay. An omitted virtual default clears that view's supplied value. Both ANSI vectors must contain exactly 16 RGBs when present; omission of the overlay clears it, while an empty vector is invalid. These fields do not reset application OSC overrides. `PaneSnapshot.color_overrides` reports OSC 10/11 and OSC 4 colors (bit `n` for index `n`) that differ from their native defaults. An explicit app override equal to its native default is not detectable in this metadata. Clients must see this metadata before sending omitted defaults: legacy family-11 decoders require both RGB fields. Old requests supplying both still decode on new peers.
- The three `.fbs` files own generated bindings. Use `planus-cli =1.3.0`: `planus rust --format false -o OUTPUT SCHEMA`. Normal builds need only the runtime. Never hand-edit/format generated Rust; fix generator-owned docs at the schema/generator boundary.
- Codec output borrows reusable builder storage. Queued writes need owned framing. Owned response decoding retains scene byte ranges through `bytes::Bytes`; converting scenes to JSON or cloning canonical frames is not the hot receive path.
- Scene revisions, matching baselines and image `(id, generation)` receipts are distinct prerequisites. Do not advance consumer cursors/resources on a rejected update. Cell widths and UTF-8 boundaries are engine facts, not an invitation to re-segment Unicode.
- Scenes carry each newly referenced image generation inline, omitting generations the consumer reports as held. `planus_v1` sends pixels; `planus_v1_sources` may send the original payload instead, with empty `pixels`, validated against the 64MiB aggregate decoded quota before decoding. Scene version2 (descriptor-only progressive scenes), its `image_descriptors` field and the `ImageResource` request/payload union members are retired: their slots stay in the schemas and decoders reject them.
- JSON path decoding uses a direct Serde string/map/sequence visitor. Keep `PathSchema`'s untagged shape for schema generation only: deriving untagged deserialization would buffer the whole value before enforcing the byte-path limit. Caller-owned JSON values and native transport allocation budgets remain separate.
- Internally tagged Serde requests needing closed argument decoding use empty struct variants (`Health {}`, `PolicyGet {}`), not unit variants: unit variants can ignore extra fields despite `deny_unknown_fields`. Keep their JSON method-only shape and structural native tables unchanged.
- Owner revision requirements differ by operation; control help identifies the workspace/window revision. View policy separates input, sizing eligibility and clipboard permissions.
- Typed `NotDispatched` and `Unknown` outcomes determine dispatch certainty; diagnostic wording never grants replay permission.
- Launch/conversation/receiver identities and OSC status remain separate facts; recovery descriptors carry no live authority. Preserve credential/path redaction in `Debug`.
- Host control operations select/create sessions explicitly; session endpoints never dispatch host administration. `SessionInfo` separates persistent session ID, host daemon incarnation and fresh session runtime instance. Registration and SSH handshakes require the exact runtime identity; logical reconnect and alias detection must not confuse different sessions sharing one daemon.
- Administration version 1 stays independent forever: `BKPA`, 24-byte header, kind 1/2, zero reserved fields and at most 8192 body bytes. Closed Serde struct variants enforce unknown-field rejection; identities are nonempty and at most 256 UTF-8 bytes per component. `NativeFamily` recognizes only a validated native response header for narrow old-server migration, never native payload decoding as administration. No transport error authorizes replay after stop dispatch.
- Notifications append native `Operation` union tag 35 without changing the existing 1..34 ordinals or native family 11. This is additive decoding, not a promise that older peers support notifications: unknown operation tags fail before dispatch. No new globally required capability is emitted. Notification requests are structural Planus unions; typed records remain response metadata. `notifications.rs` validates 256-byte identities/selectors, unique semantic kinds, 1..64 page limits and waits at most 5000ms; endpoint session clamping, host-only policy writes and durable cursor continuity remain receiving-service responsibilities. `Health` remains readable without fabricating an available store or store identity.
- Channels append native `Operation` tag 36 and `Payload` tag 4 (retired image tag 3 stays reserved), without changing native family 11, the required capability mask or remote envelope version 2. A pre-channel family-11 daemon does not support the new operation and rejects its unknown tag before dispatch. SSH bridges forward the same native frames into the selected session; neither channel references nor cursors address another session.
- Shared channel MCP uses additive `AgentRequest` tags 14–16. User `Operation::Channels` is not an agent authority route. `ChannelWake` is body-free and recipient-specific; use the existing subscription claim, validation and outcome envelope.
- `AgentRequest::ChannelWake.max_body_bytes` and `include_source` are optional/default-safe trailing wire fields. Without either, lookup stays metadata-only. An opted-in source page must pass the receiver's normal exact read authority; native pointers never carry bodies. `ChannelPost.source` and `MessageSummary.source` omit `None` in Serde to preserve existing JSON and post retry fingerprints.
- Channel history includes original text and attachment descriptors under row and aggregate UTF-8 byte limits. It pages toward older or newer posts and returns a change cursor from the same snapshot, so a frontend can render once and then resume without a race. Change pages explicitly distinguish idle/active subscriptions from terminal `Closed`; a closed final page may still carry retained changes.
- Only attachment fetches return PNG bytes. Upload and fetch use bounded padded standard Base64 in diagnostic JSON and raw vectors on native wire; owned native decoding retains a byte slice of the frame instead of copying the raster.
- Notification cursors carry store identity, sequence and the persisted cumulative observation-loss generation independently. Diagnostic JSON requires all three fields. A fresh subscription baseline acknowledges the current generation; an older resumed generation reports a gap and advances once, while future generations are rejected by the store. Cumulative historical loss alone does not imply currently unhealthy storage.
- `NotificationRequest::Push` appends a structural nested management union while keeping native family 11. All push operations require the authenticated host endpoint, including reads; remote session consoles cannot administer host destinations. `PushSubscription` and complete nested operation/request `Debug` output redact capability URLs, recipient keys, auth secrets and confirmation nonces. `Enroll.device_label` is optional/default-safe, trailing on its wire table, at most 160 UTF-8 bytes and control-free. Rotation keeps destination identity stable and advances subscription generation; `Update` changes source filters without replacing the proven subscription. Management responses expose IDs/generations, labels, filters and bounded diagnostics, never subscription secrets.
- `AgentBindingGuard` carries the exact root binding generation and actual native caller context. Backend admission must enforce it before effects or cached replies; capture `NativeContext` attests children only for that generation. Conditional `Bind.expected_revision` compares the monotonic launch counter and rotates ownership even for the same root; managed OpenCode must supply it, while other integrations retain unconditional idempotent binding. `Unbind` compares both its required `expected_revision` and exact optional conversation: `None` can reserve an unbound enrollment epoch, not launch `End`. Its wire presence flag is mandatory even for revision zero; never infer a missing revision. Stale conditional mutations return `{accepted:false,binding:{revision,conversation}}` without effects, while accepted mutations return the committed snapshot and preserve recovery/capture capability. The counter never resets on unbind/rebind, and a bound conversation generation equals its revision.

## Dependency decisions

Retain Planus's reusable builder caches and `extra-validation`, `bytes` shared response storage, `compact_str` cell strings, Serde/JSON metadata, `schemars` decoder-derived schemas, `base64` diagnostic pixels and `anyhow` validation. `serde/rc` supports shared images. The schema compiler is not a normal build dependency.

The first review found no duplicate package versions in `cargo tree --locked -p bkpr-protocol -d`; workspace duplicates originate elsewhere. Reviewed non-yanked upstream releases: [Planus 1.3.0](https://crates.io/api/v1/crates/planus/1.3.0) (MIT OR Apache-2.0), [compact_str 0.10.0](https://crates.io/api/v1/crates/compact_str/0.10.0) and [schemars 1.2.3](https://crates.io/api/v1/crates/schemars/1.2.3) (MIT). No feature removal/library replacement is justified by dependency count alone; cold-build costs were not measured.

## Verification

Protocol-only tests/rustdoc need no Ghostty build: `nix develop --command cargo test --locked -p bkpr-protocol -j 8` and `nix develop --command cargo doc --locked -p bkpr-protocol --no-deps -j 8`. Existing tests cover native framing/typed requests, malformed/aliased scenes, atomic rejected apply, raw paths and remote handshakes. Public docs also become `schemars` descriptions: exercise actual CLI `api schema` output. Apply the root coordinated workspace verification and live-artifact safety rules for related code changes.

Inline image payloads reuse maintained `png` and `flate2` (zlib-rs backend), already built for the framework and engine; no protocol-owned codec exists.
