# Terminal application boundary

`bkpr-client` projects native sessions into one physical terminal. It depends on `bkpr-protocol` and `bkpr-tui-framework`, never backend implementation crates. The `bkpr` executable supplies parsed destinations and deferred local bootstrap through `SessionTarget`; the client does not reinterpret remote path syntax.

## Ownership and entry points

- `lib.rs::run_sessions` enters the application. `app.rs` owns the physical terminal event loop, retained UI surfaces, composition order and input routing. `controller.rs` holds local navigation/layout projections and chrome content; `tiling.rs` is the shared geometry source for pane content, dividers and pointer coordinates.
- `sessions.rs::Coordinator` owns independent attachments, admission generations, reconnect policy and the shared sidebar tree. Switching visible sessions does not transfer backend workspace/pane ownership. A stale admission must not activate takeover or publish endpoint authority.
- One host daemon may serve several session endpoints. Alias checks require the same session runtime, not just a shared `daemon_id`; registration and remote admission pin `(session_id, daemon_id, session_instance_id)`. Reconnect pins the logical session separately and never replays bootstrap, takeover or input. Session retirement affects only that attachment, including multiple sessions on one SSH host.
- `transport.rs` owns framed request/receipt handling. `client_lifetime.rs::RegisteredClient` owns the sole native lifetime stream; cloned `Endpoint`s share revocation, not lifetime ownership. Registration and activation are separate. Activation is one-shot even when its receipt is ambiguous.
- Session-row stop uses `Endpoint::stop_session` over frozen BKPA with the confirmed session/host/runtime identity and original connector. It is a tracked non-observational request: backend lifetime retirement can precede its receipt. Drain that receipt, never infer success from EOF, and never retry or automatically reconnect a requested stop.
- The coordinator owns stop receipts independently of confirmation/form lifetime. Capture the exact owner generation, session identity and host; stopping an inactive owner must not select it. Suppress reconnect after stop dispatch, including ambiguous EOF, and drain the receipt before final exit or remote transport teardown. `S` explicitly exposes a sole session root without changing the default sidebar.
- `remote.rs` owns one OpenSSH child, multiplexed native connections and its transport lease. It does not reconnect or replay requests. Remote path resolution stays with the remote helper. `cancel`, `retire` and blocking `disconnect` have different drain/teardown contracts; do not substitute one for another.
- `updates.rs`, `input.rs` and `jobs.rs` bridge workers into pollable wake descriptors. Input acceptance/receipts, metadata observations and scoped job completion are distinct. Keep mutation ordering and retired-generation rejection intact; do not turn a lost receipt into replay permission.
- Pane polls request `planus_v1_sources` and report held generations so images arrive inline, in order with their scene. `pane_scene.rs` applies scenes atomically; `ViewImages` keeps the current generations plus recently dropped ones, bounded by count and bytes. The worker sends its next poll before the UI applies the previous snapshot, so a report is always one apply behind: it adds the generations it delivered but the UI has not yet applied, and the UI keeps generations it evicts until a snapshot shows that a later poll no longer reports them. Otherwise the backend omits an image the view no longer has, and the view fails. Terminal payloads (original PNG/zlib or compressed pixels) are prepared on the poll thread, never the UI thread; `HeldImages` never holds its lock across a poll.
- `pane_feedback.rs` owns the delayed 200 ms “Loading pane…” attach notice and the static “Images require Kitty graphics support” notice. Captions inherit actual pane colors; only the spinner uses warning ink.
- `diagnostics.rs` retains bounded approved technical incidents independently of toast expiry. Failure identities survive cached input rejection and completion reports; allocate them only on failure, not per key. Unknown outcomes stay typed through completion context and never authorize replay. Details is a separate read-only modal, preserving pending/ambiguous forms, paste suppression and full pointer-gesture ownership.
- `notification_updates.rs` owns bounded cancellable live subscriptions outside the management pool, with one reusable runtime per observer and no empty-page UI wakeups. New attachments/store identities establish a fresh baseline; errors do not retry or replay.

## Presentation and authority

- `tree.rs`, `finder.rs` and popup models consume published backend facts. `metadata.rs`/`ci.rs` format supplied metadata; provider/Git/process acquisition belongs to the backend. Client annotations cannot overwrite authoritative status or membership.
- The sidebar scrollbar uses the same display-row viewport as text, artwork and hit testing. When visible, it reserves the last sidebar column without moving the pane divider. Joined popup graphics must leave the scrollbar glyphs unobscured.
- Finder invalidation includes terminal diagnostics even when the registry revision is unchanged. Its semantic key avoids rebuilding the index for unrelated view/lease metadata; keep query and selected pane identity through refresh.
- Finder, recovery and theme pickers share the framework's `PickerLayout` for section bounds, clipping, pointer coordinates and rounded Unicode borders. Geometry never depends on material readiness. `appearance::picker_backgrounds` owns the input tint and raised body colors; `app.rs` requests existing cached materials for every card without serial readiness gating.
- `recovery_picker.rs` validates owner-local recovery lists and exact descriptors, then performs one worker-only native resume with current configuration. Revalidate eligibility before invocation; cancellation before admission differs from draining an invoked mutation. Never replay unknown outcomes or substitute a fresh conversation.
- Recovery uses stacked full-width results/details cards. Saved pane titles are metadata, not conversation names. Reuse the shared harness icon/color mapping and keep full native IDs searchable even when display columns clip them.
- `recovery_ui.rs` owns picker generations, read-only policy, pending starts and published native-binding observations. Capture the original session/attachment; late results may update facts but must not reopen a retired overlay or steal focus. Native process creation isn't authenticated conversation binding. Details retain wrapped text and paint state; metadata browsing doesn't attach hidden views.
- `keyguide::Availability` samples effective bindings into an exact stack bitset; use that same snapshot for cache invalidation and rendering. Don't add per-feature flag bits or popup shortcut footers. The bottom-left guide uses `OverlayPolicy::COMPANION` above modals without claiming their keys; pending/read-only/empty-result and focused-details changes must update its contents.
- CI refresh hints follow the exact selected CI source, not incidental registry/paint revision differences. Mutation and clipboard dispatch still validate their current painted source; don't weaken those checks to stabilize hints.
- `selection.rs`, `scrollback.rs` and `search.rs` retain view-local state. Coordinates, revisions and view identity must remain associated with their original attachment. Focus and pointer gestures must not leak releases to a replacement pane/view.
- `resizing.rs` owns one exact-revision layout mutation flight. Divider double-clicks reuse that worker path, qualify the same separator/owner/geometry within 500 ms and invalidate on motion, foreign revisions or retired focus. Equalization preserves descendant ratios/minima; consume the complete gesture. Normal completion and retirement are silent, but rejected/unknown mutation outcomes remain visible.
- Search query suffix layout is shared by paint, cursor and role spans. Use the framework's whole-grapheme cell geometry for measurement and clipping; keep query, caret and highlight bounds tied to the same painted layout.
- `chrome_graphics.rs` adapts product artwork/material requests to the framework. The framework owns physical rendering, capabilities, resource lifetimes and terminal restoration. No second output loop or terminal emulator belongs here.
- The client selects `$XDG_CACHE_HOME/bkpr/chrome` or an absolute HOME's `.cache/bkpr/chrome`; the framework performs worker-only caching. Tests explicitly pass no cache or private paths, never normal profile caches. Register newly published PNG uploads before scene rendering; registration performs no codec or filesystem work. Reusable popup/hover materials persist, but layout-specific compositions and native pane resources do not.
- Theme policy lives in `appearance.rs`, `themes.rs` and `project_colors.rs`; source scene cells remain canonical. Restore transient title effects before retained styling/layout, and leave inactive animation clocks dormant.
- Working title sweeps use cached normalized variants of the assigned bee hue. `appearance::project_color_tones` owns the actual-background contrast target and muted ink policy; the framework maximizes in-gamut chroma uniformly across hues. The client owns band width, spacing, terminal-cell speed and cadence. Spacing is independent of band width so widening cannot slow repetition. Unknown/native-only RGB evidence keeps titles static. Project palette invalidation includes tone changes even when base bee bytes are unchanged.
- Pane image viewing is client-local: Alt-left-click picks canonical image placements and pins an immutable resource in the framework viewer. Consume the complete UI gesture, modal keys and paste; preserve ordinary pane input and release retained resources on dismissal.
- `project_colors.rs::ProjectColors` owns project ordinals across all attachments. Qualify canonical common Git paths by local filesystem or SSH route, never by session/generation or a backend color slot. Sidebar, finder and popovers share the owner's projection; unknown owners stay muted. Live assignments remain stable and retired identities are bounded.
- Read-only input, sizing eligibility and clipboard consent are independent policies. Clipboard replies remain device traffic, not keystrokes. Original offers, pane/view identity and exact byte payloads must survive asynchronous consent.
- `identity_copy.rs` owns explicit metadata clipboard exports. Conversation and launch IDs are distinct fields; copy original bytes, not sanitized/clipped display text. Sidebar and Finder share typed metadata buttons. Revalidate attachment generation, foreground process birth and native binding generation immediately before host output; retire gestures on focus/modal changes. Read-only input does not forbid user copy; deny policy and existing consent/paste exchanges still apply. User exports reuse selection's coordinated clipboard writer and never become pane input.
- `desktop.rs` owns best-effort per-TUI presentation and bounded source callbacks, not backend deliveries. Multiple TUIs may independently notify. Suppress only a current attended source with positively observed physical focus; `App.host_focused` is also used for synthetic session projection and is not physical evidence. Activation rechecks attachment/session/process/launch/binding identity and uses ordinary owner navigation; terminal writes are never presentation receipts.

## Dependencies and review

Termwiz supplies maintained input parsing; Unicode crates, Nucleo and Textwrap supply grapheme handling, fuzzy matching and wrapping. Tokio/Tokio-util provide worker I/O, cancellation and compatibility with Yamux's futures I/O. The small futures executor is used by synchronous remote connection workers, not the terminal loop. Avoid replacing these with local parsers/executors to reduce dependency counts. Check enabled features and actual callers before trimming shared workspace features.

Public consumers see `Options`, attachment targets, remote helpers and typed transport/lifetime APIs. Keep their docs about immediate contracts, especially blocking behavior, revocation and unknown outcomes. Private module `pub` visibility is not a reason to export application internals.

Run coordinated native workspace tests, strict all-target Clippy, formatting and changed-path smoke as specified by the root guidance. Permission/lifetime fixtures must execute as the host user with private HOME/XDG and owned sockets/processes. Preserve live public executable paths during product relinks. UI behavior needs actual isolated terminal-surface proof; a typed receipt is not presentation evidence.
